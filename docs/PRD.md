# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
COZY 커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

### 1.4 이번 문서의 범위
이 문서는 주문하기 화면과 관리자 화면의 프런트엔드 요구사항을 정의한다. 백엔드 API와 데이터베이스의 세부 설계는 별도 기술 설계에서 정의한다.

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면 PRD

### 4.1 목표 및 사용자
- 사용자가 커피 메뉴와 추가 옵션을 선택해 장바구니에 담고, 주문을 제출할 수 있어야 한다.
- 대상 사용자는 별도 가입이나 로그인 없이 커피를 주문하려는 방문자다.
- 결제는 앱에서 처리하지 않는다. 주문 제출은 주문 정보를 앱에 등록하는 단계다.

### 4.2 화면 구성
1. **상단 내비게이션**
   - 브랜드명 `COZY`를 표시한다.
   - `주문하기`와 `관리자` 메뉴를 제공한다.
   - `주문하기`는 현재 화면임을 시각적으로 표시하고, `관리자`는 관리자 화면으로 이동한다.
2. **메뉴 목록**
   - 메뉴를 카드 형태로 표시한다. 각 카드에는 메뉴 이미지, 메뉴명, 기본 가격, 짧은 설명, 추가 옵션, `담기` 버튼이 포함된다.
   - 와이어프레임 예시 메뉴는 아메리카노(ICE) 4,000원, 아메리카노(HOT) 4,000원, 카페라떼 5,000원이다. 실제 메뉴와 가격은 관리되는 메뉴 데이터를 기준으로 표시한다.
   - 옵션은 메뉴별로 설정한다. 와이어프레임의 예시는 샷 추가(+500원), 시럽 추가(+0원)이며, 선택 옵션과 추가 금액을 함께 표시한다.
3. **장바구니**
   - 담긴 각 메뉴의 메뉴명, 선택 옵션, 수량, 항목 금액을 표시한다.
   - 장바구니 전체 금액을 표시하고, `주문하기` 버튼을 제공한다.
   - 항목 금액은 해당 메뉴의 기본 가격과 선택 옵션 금액을 합한 단가에 수량을 곱해 계산한다. 전체 금액은 모든 항목 금액의 합이다.
   - 빈 장바구니에는 빈 상태 안내를 표시하고, 주문 제출을 할 수 없도록 한다.

### 4.3 사용자 흐름 및 동작
1. 사용자가 메뉴 카드에서 필요한 옵션을 선택한다.
2. `담기`를 누르면 선택한 메뉴와 옵션이 장바구니에 추가되고, 장바구니와 총액이 갱신된다.
3. 동일한 메뉴와 동일한 옵션 조합을 다시 담으면 한 항목으로 합산하고 수량을 늘린다. 옵션 조합이 다르면 별도 항목으로 표시한다.
4. 사용자가 장바구니의 `주문하기`를 누르면 장바구니 내용을 주문으로 제출한다.
5. 주문이 성공하면 성공 안내를 표시하고 제출한 장바구니를 비운다. 제출에 실패하면 오류 안내를 표시하고 장바구니를 유지해 재시도할 수 있게 한다.

### 4.4 기능 요구사항
- **메뉴 표시:** 판매 가능한 커피 메뉴와 가격 및 옵션을 표시한다. 이미지나 설명이 없는 경우에도 메뉴명과 가격은 확인할 수 있어야 한다.
- **옵션 선택:** 각 메뉴의 옵션은 선택 여부를 명확하게 표현한다. 선택하지 않은 옵션은 금액에 포함하지 않는다.
- **장바구니 추가:** 메뉴를 장바구니에 담은 직후 장바구니 항목, 수량, 금액이 최신 상태로 표시되어야 한다.
- **금액 계산:** 메뉴 단가와 옵션 금액을 기준으로 항목 금액 및 총액을 계산하며, 화면의 모든 금액은 원 단위로 표시한다.
- **주문 제출:** 장바구니가 비어 있지 않을 때 주문 제출을 허용한다. 제출 중에는 중복 제출을 방지하고 진행 상태를 표시한다.
- **결과 안내:** 주문 성공과 실패를 사용자가 알아볼 수 있게 안내한다. 오류 시 기존 장바구니 항목과 선택 내용은 보존한다.
- **화면 이동:** 상단 내비게이션에서 주문하기 화면과 관리자 화면으로 이동할 수 있다.

### 4.5 예외 및 상태
- 메뉴를 불러오는 동안 로딩 상태를 표시하고, 불러오기에 실패하면 오류와 다시 시도할 방법을 제공한다.
- 메뉴가 없으면 메뉴가 없다는 안내를 표시한다.
- 주문 제출에 실패해도 장바구니를 초기화하지 않는다.
- 옵션이나 메뉴 데이터가 변경되어 제출 시 가격/판매 가능 상태가 유효하지 않다면 주문을 제출하지 않고 사용자에게 다시 확인하도록 안내한다.

### 4.6 레이아웃 및 접근성
- 데스크톱에서는 메뉴 카드를 여러 열로 배치하고 장바구니를 메뉴 목록 아래에 표시한다. 와이어프레임은 메뉴 카드 3개 열을 예시로 한다.
- 화면 폭이 좁아지면 카드 열 수를 줄여 가로 스크롤 없이 읽고 조작할 수 있게 한다.
- 버튼, 체크박스, 내비게이션은 키보드로 조작할 수 있고, 각 입력에는 메뉴명과 옵션 등 식별 가능한 이름을 제공한다.
- 옵션 가격과 총액은 색상만으로 구분하지 않고 텍스트로도 명확히 표시한다.

### 4.7 인수 기준
- 메뉴 카드에서 옵션을 선택하고 `담기`를 누르면 해당 옵션과 금액이 장바구니에 반영된다.
- 동일한 메뉴·옵션 조합을 두 번 담으면 수량은 2가 되고, 다른 옵션 조합은 별도 항목으로 보인다.
- 기본 가격 4,000원인 아메리카노(ICE)에 샷 추가(+500원)를 선택해 1개, 기본 가격 4,000원인 아메리카노(HOT)를 2개 담으면 항목 금액은 각각 4,500원과 8,000원, 총액은 12,500원으로 표시된다.
- 빈 장바구니에서는 주문 제출이 불가능하며, 주문 제출 중에는 중복 요청을 할 수 없다.
- 성공 시 성공 안내와 장바구니 초기화가 이루어지고, 실패 시 오류 안내와 기존 장바구니 유지가 이루어진다.
- 좁은 화면에서도 메뉴 정보, 옵션, 장바구니 총액 및 주요 버튼을 가로 스크롤 없이 이용할 수 있다.

### 4.8 미결정 사항
- 장바구니에서 수량을 변경하거나 항목을 삭제하는 기능은 와이어프레임에 표현되어 있지 않다. 구현 범위 확정 시 해당 기능의 필요 여부와 조작 방식을 결정한다.
- 주문 제출 후 보여줄 상세 확인 화면/정보와 주문 취소 가능 여부는 별도 주문 처리 요구사항에서 결정한다.

## 5. 관리자 화면 PRD

### 5.1 목표 및 사용자
- 관리자가 주문 건수와 메뉴별 재고를 확인하고, 재고를 조정하며, 접수된 주문을 처리할 수 있어야 한다.
- 이 화면은 매장의 주문 및 재고를 관리하는 운영자를 대상으로 한다.
- 기본 사항에 따라 인증 기능은 범위에서 제외한다.

### 5.2 화면 구성
1. **상단 내비게이션**
   - 브랜드명 `COZY`와 `주문하기`, `관리자` 메뉴를 표시한다.
   - `관리자`는 현재 화면임을 시각적으로 표시하고, `주문하기`는 주문 화면으로 이동한다.
2. **관리자 대시보드**
   - 총 주문 수, 주문 접수 수, 제조 중 수, 제조 완료 수를 요약해 표시한다.
   - 각 수치는 현재 주문 상태별 건수이며, 총 주문 수는 표시 대상인 전체 주문 건수다.
3. **재고 현황**
   - 메뉴별 카드에 메뉴명, 현재 재고 수량, 수량 증가(+) 및 감소(-) 버튼을 표시한다.
   - 재고 수량은 정수 단위로 표시한다.
4. **주문 현황**
   - 주문별 접수 시각, 주문 메뉴 및 수량, 주문 금액, 현재 처리 단계에 해당하는 동작을 표시한다.
   - 와이어프레임은 주문 접수 대기 건의 `주문 접수` 버튼을 예시로 한다.
   - 주문이 없으면 주문이 없다는 빈 상태를 표시한다.

### 5.3 사용자 흐름 및 동작
1. 관리자가 화면에 진입하면 주문 상태별 건수, 메뉴별 재고, 처리할 주문 목록을 확인한다.
2. 재고 카드의 `+` 또는 `-` 버튼을 누르면 해당 메뉴 재고를 1개 증감하고 최신 수량을 표시한다.
3. 주문 현황에서 `주문 접수`를 누르면 해당 주문을 접수 상태로 변경하고, 요약 수치 및 주문 목록을 갱신한다.
4. 처리에 성공하면 갱신된 값을 표시한다. 실패하면 오류를 안내하고, 저장되지 않은 변경을 성공한 것처럼 표시하지 않는다.

### 5.4 기능 요구사항
- **대시보드 요약:** 주문 상태별 건수를 주문 데이터와 일치하게 표시한다. 상태 변경 후 관련 수치가 갱신되어야 한다.
- **재고 조회:** 관리 중인 커피 메뉴별 현재 재고를 표시한다.
- **재고 조정:** `+`는 수량을 1 증가시키고 `-`는 1 감소시킨다. 재고는 0 미만이 될 수 없으며 0일 때 감소 동작은 비활성화한다.
- **주문 조회:** 주문 시각, 메뉴명, 메뉴별 수량, 총 주문 금액 및 처리 상태를 식별할 수 있게 표시한다.
- **주문 접수:** 접수 대기 주문만 접수할 수 있다. 처리 중에는 중복 입력을 막고, 성공하면 목록과 집계에 반영한다.
- **결과 안내:** 재고 변경 또는 주문 접수가 실패하면 사용자가 오류를 알 수 있어야 하며, 재시도할 수 있도록 기존 표시를 보존하거나 서버의 최신 상태를 다시 불러온다.
- **화면 이동:** 상단 내비게이션에서 주문 화면과 관리자 화면을 오갈 수 있다.

### 5.5 예외 및 상태
- 주문, 재고 정보를 불러오는 중에는 로딩 상태를 표시한다. 불러오기에 실패하면 오류와 다시 시도할 방법을 제공한다.
- 메뉴가 없으면 재고 현황에 빈 상태를 표시한다.
- 재고 수량이 0인 메뉴는 0으로 표시하고 감소시킬 수 없다.
- 다른 요청으로 재고나 주문 상태가 먼저 변경되어 갱신 요청이 거부되면 최신 정보를 반영하고 결과를 사용자에게 알린다.
- 주문 접수 요청이 실패해도 해당 주문을 접수 완료로 표시하거나 대시보드 건수를 임의로 변경하지 않는다.

### 5.6 레이아웃 및 접근성
- 대시보드, 재고 현황, 주문 현황을 구분된 영역으로 배치한다.
- 데스크톱에서는 재고 메뉴를 여러 열로 표시하며, 좁은 화면에서는 열 수를 줄여 가로 스크롤 없이 확인하고 조작할 수 있게 한다.
- 재고의 `+`, `-` 버튼은 어떤 메뉴의 수량을 변경하는지 보조 기술로도 식별할 수 있는 이름을 제공한다.
- 버튼은 키보드로 조작 가능해야 하며, 비활성화 상태와 주문 처리 결과를 색상만으로 전달하지 않는다.

### 5.7 인수 기준
- 대시보드의 총 주문 및 각 상태 건수가 실제 주문 목록의 상태별 건수와 일치한다.
- 재고가 10개인 메뉴에서 `+`를 한 번 누르면 11개, `-`를 한 번 누르면 9개로 표시된다.
- 재고가 0개일 때 감소시킬 수 없으며, 음수 재고가 표시되거나 저장되지 않는다.
- 접수 대기 주문의 `주문 접수`를 누르면 요청 성공 후 주문 상태와 대시보드 집계가 함께 갱신된다.
- 재고 변경 또는 주문 접수가 실패하면 오류 안내가 표시되고, 실패한 변경을 완료된 값으로 표시하지 않는다.
- 주문 및 재고가 없는 경우 각각 알아볼 수 있는 빈 상태가 표시된다.
- 좁은 화면에서도 주문 정보, 재고 수량, 주요 버튼을 가로 스크롤 없이 이용할 수 있다.

### 5.8 미결정 사항
- 와이어프레임에는 `주문 접수` 이후의 제조 시작 및 제조 완료 동작이 표현되어 있지 않다. 대시보드에 제조 중·제조 완료 집계가 포함되므로, 이 상태로 변경하는 버튼과 허용 상태 전이를 확정해야 한다.
- 재고를 주문 접수 시 자동 차감할지, 제조 완료 시 차감할지, 또는 관리자가 수동 조정만 할지는 정해져 있지 않다.
- 주문 현황의 정렬 순서, 목록 페이지 처리, 완료 주문 보관/노출 방식은 별도 운영 정책에서 결정한다.
